## Falhas e problemas

### 1. [IMPORTANTE] README (G3): `bundle install` e `yarn ios` falham com o Ruby do sistema do macOS

Passos (do "Início rápido", num macOS com o Ruby do sistema 2.6, que é o padrão):
1. `cd mobile && yarn install && cp .env.example .env`
2. `cd ios && bundle install`

Esperado: instala o CocoaPods do Gemfile.
Obtido: `Gem::Ext::BuildError: ERROR: Failed to build gem native extension` no `json 2.7.6` ("The compiler failed to generate an executable file"). Com isso, `bundle exec pod install` falha (`Could not find gem 'cocoapods'`).

Contorno: `pod install` com o CocoaPods do Homebrew (1.16.2) funcionou (97 pods). O README só cita isso na seção iOS, não no "Início rápido".

Mas o passo seguinte também falha: `yarn ios` sempre tenta `bundle install` na primeira vez, porque o `@react-native-community/cli` não tem o hash do Podfile no cache e roda a instalação dos pods pelo Gemfile. Resultado: "✖ Installing Ruby Gems / error Something went wrong while installing CocoaPods. Please run pod install manually." Esse erro aparece mesmo com os pods já instalados.

Para buildar, rodei `xcodebuild -workspace FiapSchool.xcworkspace -scheme FiapSchool -configuration Debug -sdk iphonesimulator -destination id=<udid> build` → `** BUILD SUCCEEDED **`. Também daria para buildar pelo Xcode.

Sugestão para o README: dizer que o Gemfile pede um Ruby que compile extensões nativas (rbenv/Homebrew ≥ 3.x), dar `pod install` como plano B já no "Início rápido" e oferecer "abrir `ios/FiapSchool.xcworkspace` no Xcode e dar Run" como alternativa ao `yarn ios`.

### 3. [SUGESTÃO] `yarn format:check` do mobile fica vermelho depois de seguir o README

O template do RN tem `mobile/.bundle/config` com `BUNDLE_PATH: "vendor/bundle"`. Com isso, o `bundle install` do README grava as gems em `mobile/vendor/bundle`, e o `.prettierignore` não ignora `vendor/`. Resultado: `yarn format:check` → "Code style issues found in 22 files", todos em `vendor/bundle/ruby/2.6.0/gems/*`. O `.gitignore` já ignora a pasta, mas o Prettier não. Correção: acrescentar `vendor` ao `mobile/.prettierignore` (e conferir o `eslint`, que hoje passa). Depois de apagar `vendor/`: "All matched files use Prettier code style!".

### 4. [SUGESTÃO] Troubleshooting do yarn 3 descreve um sintoma diferente do que ocorreu aqui

Com um `~/workspace/.yarnrc.yml` de yarn 3 acima do repo, o `yarn install` em `api/` (sem `YARN_IGNORE_PATH`) **não** deu o "Internal Error … lockfile" que o Troubleshooting descreve. Ele rodou o yarn 3.6.4 até o fim ("Done with warnings"), reescreveu o `api/yarn.lock` e criou `api/.yarn/`. Desfiz com `git checkout yarn.lock` e reinstalei com `YARN_IGNORE_PATH=1` (1.22.22). Isso só acontece com um yarn 3 acima do repo, mas vale citar esse sintoma também ("se o `git status` mostrar `yarn.lock` alterado e `.yarn/`…").

### 5. [SUGESTÃO] Diferenças visuais com o Figma (M12)

- Logo do login e da splash serrilhado/borrado (PNG 1×): pendência conhecida, depende do export do Figma.
- Senha com bolinhas (`●`, `secureTextEntry` nativo do iOS) no lugar dos asteriscos do Figma. É o comportamento padrão da plataforma; registro só para constar.
